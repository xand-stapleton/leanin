Lean Statement

2 * (0 + 1 + ... + n) = n * (n + 1)
Read this as: the sum from $0$ through $n$ is $n(n+1)/2$. The theorem multiplies both sides by $2$, avoiding division in the natural numbers.

For $n=0$, both sides are zero. For the induction step, suppose $2(0+\cdots+n)=n(n+1)$. The next sum is the old sum plus $n+1$, so doubling it gives

\[n(n+1)+2(n+1)=(n+1)(n+2).\]

That is exactly the required formula with $n$ replaced by $n+1$.

Why This Proof Matters

This proof introduces induction over natural numbers and uses Finset.range to represent a finite sum.

Schematic Outline

  1. State the sum from $0$ through $n$ as a sum over Finset.range (n + 1).
  2. Remember the indexing convention: Finset.range 4 contains $0,1,2,3$, not $4$.
  3. Induct on $n$.
  4. Use simplification for the base case.
  5. In the step case, rewrite the range sum so the final term is explicit.
  6. Substitute the induction hypothesis and finish the algebra.

Lean Proof

import Mathlib

/--
Twice the sum `0 + 1 + ... + n` is `n * (n + 1)`.

The sum through `n` is encoded as `∑ i in Finset.range (n + 1), i`, because
`range m` contains the natural numbers strictly below `m`.
-/
theorem sum_first_n_naturals (n : ℕ) :
    2 * (∑ i ∈ Finset.range (n + 1), i) = n * (n + 1) := by
  induction n with
  | zero =>
      -- The sum over `range 1` is just `0`, so the goal computes away.
      simp
  | succ n ih =>
      -- Rewrite the sum through `n + 1` as the previous sum plus the final term.
      rw [Finset.sum_range_succ]

      calc
        2 * ((∑ i ∈ Finset.range (n + 1), i) + (n + 1))
            = 2 * (∑ i ∈ Finset.range (n + 1), i) + 2 * (n + 1) := by
              ring
        _ = n * (n + 1) + 2 * (n + 1) := by
              rw [ih]
        _ = (n + 1) * ((n + 1) + 1) := by
              ring

Proof Breakdown

Finset.range (n + 1)
The finite set $\{0,1,\ldots,n\}$, written in Lean as all natural numbers below $n+1$.
induction n with
Splits the proof into the base case $0$ and the successor case. In the successor branch, Lean's name n refers to the previous number, and the branch proves the formula for $n+1$.
ih
The induction hypothesis: the theorem already proved for the previous value of $n$.
rw [Finset.sum_range_succ]
Rewrites a range sum by peeling off its final term.
calc
Writes a chain of equalities, just like a traditional line-by-line calculation.

After rw [Finset.sum_range_succ], the large sum has become 'the old sum plus the new last term'. The first ring distributes the outer factor $2$. The line rw [ih] is the only place where induction does any proper work: it replaces twice the old sum by $n(n+1)$. The final ring verifies the remaining elementary identity.

Caveat

This proof uses the convention that Finset.range (n + 1) represents the indices $0$ through $n$. As an aside, given its purpose, I'm surprised Lean didn't adopt inclusive-inclusive sum ranges rather than inclusive-exclusive. There must be a reason (maybe parity with Python/Go etc), so there's an almost 100% chance I'm too ignorant to see why. Other statements of the same formula may sum from $1$ to $n$, which changes the indexing details but not the idea of the induction. I did it this way as it's how I first learnt induction in my A-levels.

The binder notation $\in$ also requires a new Lean/Mathlib version. I was initially wondering why using in worked locally but not on Lean Web (uses Lean v4.34.0-rc1). This was why. Surprisingly, I asked a clanker (GPT 5.1) and it couldn't tell me.
