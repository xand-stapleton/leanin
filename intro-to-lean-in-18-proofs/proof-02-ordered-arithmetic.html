Lean Statement

a ≤ b → a + c ≤ b + c
Read this as: if $a\le b$, then adding the same integer $c$ to both sides preserves the inequality: $a+c\le b+c$.

The distance between the two sides does not change:

\[(b+c)-(a+c)=b-a.\]

The assumption $a\le b$ says that this difference is nonnegative, so $a+c\le b+c$.

Why This Proof Matters

This proof shows that inequality facts depend on the type of the variables and the ordered algebraic structure available for that type.

The inequality is declared as the named theorem parameter h : a ≤ b, so it is already available in the local context when the proof begins.

Schematic Outline

  1. Work over the integers, where linarith applies directly.
  2. Take $a\le b$ as an explicit hypothesis, named h, in the theorem statement.
  3. Begin the proof with the goal $a+c\le b+c$ and h already available.
  4. Let Lean's linear arithmetic tactic derive the new inequality from h.

Lean Proof

import Mathlib

/--
Adding the same integer to both sides preserves an inequality.

This version is concrete: over `ℤ`, `linarith` can recognise the goal as linear
arithmetic.
-/
theorem ordered_arithmetic (a b c : ℤ) (h : a ≤ b) :
    a + c ≤ b + c := by
  linarith

Proof Breakdown

(h : a ≤ b)
Declares $a\le b$ as a named hypothesis, making h available as soon as the proof starts.
linarith
Combines linear equalities and inequalities from the local context.
(a b c : ℤ)
Declares all three variables as integers, which tells Lean exactly which arithmetic theory to use.

At the start, the context already contains h : a ≤ b and Lean displays the goal ⊢ a + c ≤ b + c. Mathematically, these are the assumption $a\le b$ and target $a+c\le b+c$. The final tactic uses h and leaves no goals.

A more theorem-driven proof can replace linarith with exact add_le_add_right h c. The two versions teach complementary habits: use a named monotonicity lemma when you know it, or use linear-arithmetic automation when several simple inequalities must be combined.

Native Lean Version

For natural numbers, Lean's core library already contains the monotonicity lemma needed for the same proof idea, so this version does not import mathlib.

/--
Native Lean version over natural numbers.
-/
theorem native_ordered_arithmetic (a b c : Nat) (h : a ≤ b) :
    a + c ≤ b + c := by
  exact Nat.add_le_add_right h c

Native Lean Breakdown

Nat
Uses Lean's built-in natural numbers rather than mathlib's broader ordered algebra hierarchy.
(h : a ≤ b)
Names the inequality hypothesis directly in the theorem statement.
Nat.add_le_add_right h c
The core Lean theorem saying that adding the same natural number on the right preserves $\le$.
exact
Closes the goal with that monotonicity theorem.

Caveat

The theorem is stated over ℤ to keep the proof short. A more general version would use an ordered algebraic typeclass, and the proof might use a library lemma such as addition monotonicity instead of linarith. Not that it's really any better, but I suppose one could also use omega instead of ring, too.
