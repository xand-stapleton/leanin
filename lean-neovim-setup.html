Set Up Lean in Neovim

Setting up a Lean 4 and Neovim environment on macOS.

Why Neovim?

The official Lean installation pages recommend VS Code with the Lean 4 extension, and that is the best route for most people. Basically everyone I know loves VS Code. It's easy and ubiquitous. The Lean extension gives syntax highlighting, completion, and a polished Lean workflow with very little configuration.

Even with this, my preference is still Neovim. Maybe it's a little contrary, but the manual installation page also explicitly points to Neovim and lean.nvim as well-supported, so that's nice. I think it's probably worth the little extra effort though. Many of us agree (Neo)Vim is a prime example of almost perfect design, among the echelons of the Bic lighter (or equivalently the Clipper here in the UK), Pentel's P200 series of pencils, Herman Miller's Eames and Aeron chairs, or the humble Lego block. Of course, part of good design is taste, (Neo)Vi(M) is extremely ergonomic and has been my editor of choice since 2016, but part of good design is longevity: Neovim was designed to be the most comfortable and efficient editor possible, as opposed to an ecosystem. It's also available in a terminal over SSH and installs on every platform (that being said VS Code is also exceptionally well supported to give it credit where credit is certainly due). VS Code is open source in important ways, and the Lean extension is undoubtedly excellent, but writing code should not depend too heavily on a project that Microsoft could de-prioritise or reshape to suit their business model. In fact, I was originally rather fond of Atom. Atom was VS Code's predecessor that first introduced the world to Treesitter, but it quickly became a member of the Microsoft graveyard (though Atom was not without its flaws: being a primitive Electron app it was extremely slow for modest files and was horrifically RAM intensive).

Install the Tools

This guide assumes that Homebrew is already installed. If this is not the case, follow the instructions on: brew.sh

First check that git is available. On modern macOS this may trigger installation of the Xcode Command Line Tools if they are missing:

git --version

Install Neovim if it is not already present:

brew install neovim

Install Lean through elan, the Lean toolchain manager:

curl https://elan.lean-lang.org/elan-init.sh -sSf | sh

Choose the default installation option when prompted, then add the elan executables to the current shell:

source $HOME/.elan/env

Check that Lean and Lake are available:

lean --version
lake --version

Add Lean Support to Neovim

The main Neovim plugin is lean.nvim. With Neovim 0.12 or later, its README gives a compact setup using Neovim's built-in package support:

vim.pack.add { "https://github.com/Julian/lean.nvim" }
vim.g.lean_config = { mappings = true }
As an aside, I recently moved to Neovim's built in package manager over Pathogen. I think I prefer Pathogen.

Configure the Language Server

lean.nvim supplies Neovim's configuration for leanls, Lean's language server, and enables it automatically. If you keep an explicit list of language servers in your Neovim configuration, add leanls after loading the plugin:

vim.lsp.enable("leanls")

There is no separate language-server executable to install. The plugin starts lake serve inside Lake projects and falls back to lean --server for standalone files, so it uses the Lean version selected by the project's lean-toolchain file. After opening a .lean file, run :checkhealth vim.lsp and confirm that leanls appears under the active clients.

Try the Infoview

Open a Lean file in the project and try a minimal theorem:

example (p q : Prop) : p ∧ q → q ∧ p := by
  intro h
  exact ⟨h.2, h.1⟩

The Infoview opens automatically. To toggle it manually, run :LeanInfoviewToggle or press <LocalLeader>i (\i with Neovim's default local leader).

Lean's Unicode abbreviations work directly in Insert mode: type \alpha followed by Space to produce α.

The essential feedback loop is: write a line, inspect the goal state, refine the proof, and repeat. That loop is the whole point of using an editor with Lean language-server support rather than treating Lean as a batch compiler.

Create a Lean Project

For a small test project, create a new Lake package and build it:

lake new foobar
cd foobar
lake build

Install mathlib in a Project

The mathlib library is installed as a dependency of each project rather than as one global package. For a new mathlib-based project, use the official mathlib template:

lake +leanprover-community/mathlib4:lean-toolchain new my-mathlib-project math
cd my-mathlib-project
lake exe cache get
lake build

The Lean community project installation guide also gives this shorter form:

lake +v4.24.0 new my_project math

Here, math adds mathlib to the new project's dependencies. The +v4.24.0 prefix selects a sufficiently recent version of Lake for creating the project; it does not determine the Lean version the finished project will use. Enter the new directory and run lake update, followed by the cache and build commands above.

lake exe cache get downloads mathlib's precompiled files. Do not skip it: compiling all of mathlib locally would take much longer. Each project records its own compatible Lean and mathlib versions in lean-toolchain and lake-manifest.json.

To check the installation, create a file named Main.lean in the project containing:

import Mathlib

#check Nat.Prime

Then compile it using the project's environment:

lake env lean Main.lean

If that command prints the type of Nat.Prime without an import error, mathlib is ready. Open Neovim from the project directory so that leanls selects the same toolchain and dependency set.

Existing Projects

If you clone an existing Lean project, enter the project folder and, when it depends on mathlib, fetch the precompiled cache before building:

git clone https://github.com/<owner>/<repository>.git
cd <repository>
lake exe cache get
lake build

Optional Pre-Configured Dotfiles

If you would rather start from a complete configuration, you can use or borrow from my Neovim dotfiles. The changes are fairly uncontroversial and stay close to ordinary Neovim, but once Lean itself is installed they provide Lean support out of the box: lean.nvim, language-server completion and diagnostics, the Infoview, and the associated mappings.

The dotfiles also include Lean and mathlib snippets through LuaSnip. These provide expandable templates for common structures such as imports, theorems, lemmas, calculation blocks, rewrites, and induction proofs.
